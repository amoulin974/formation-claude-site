# Synthèse

*10 minutes.*

## Ce qu'il faut retenir

1. **Un LLM produit du plausible.** Un agent lui donne le moyen de vérifier. La qualité du travail dépend de la qualité de ce moyen : tests, build, critères d'acceptation.
2. **Le contexte est la ressource à gérer.** `CLAUDE.md` pour ce qui est durable, `/clear` entre les tâches, des notes versionnées pour ce qui doit survivre à une session ou à un changement de poste.
3. **La méthode est celle d'un bon développeur**, rendue explicite : explorer, planifier, tester d'abord, avancer par petits incréments, relire chaque diff.
4. **Ce qui doit arriver passe par une permission ou un hook.** Ce qui devrait arriver passe par une instruction, une skill ou un sous-agent.
5. **Vous restez responsable** de chaque ligne commitée, comme vos étudiants le sont de chaque ligne rendue.

## Le livrable final

Dans les deux semaines suivant la séance 3, déposez :

- [ ] un dépôt, personnel ou de cours, contenant un `CLAUDE.md` et au moins une skill que vous utilisez réellement ;
- [ ] une note courte, une page au plus : ce qui a marché, ce qui a échoué, et une idée concrète d'intégration dans vos enseignements ;
- [ ] votre fiche activité de l'atelier pédagogique, éventuellement retravaillée.

## Votre avis

Le questionnaire de satisfaction vous sera communiqué à la fin de la séance. Les retours servent à faire évoluer ce site pour les prochaines sessions.
